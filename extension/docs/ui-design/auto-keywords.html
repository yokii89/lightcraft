规格卡

入口
左侧「扩展」区块 →「自动关键字」；面板停靠在右侧，默认宽 320 px，可拖到 720 px。
服务
自建 Python 服务（extension/server/server.py）承载 tencent/WeVisOne-VL-2B；/v1/chat/completions + Bearer token，只允许 http 本机地址；懒启动，空闲 5 分钟自动退出。
送图
按当前编辑设置渲染 1024 px 长边，JPEG 质量 85，Base64 内联；不送原图。
输出
固定 8 个分类之一 + 2–8 个自由关键字，保存为 父级|分类|关键字，父级默认 AI。
写入
整批一个 Op::Batch，一次撤销；关掉自动写 XMP 时只进目录，打开时同步 sidecar。
范围
选中照片 / 当前视图 / 整个图库；跳过视频；可跳过已有关键字的照片。
长任务
后台逐张处理，进度与取消同时出现在左下角活动栈；关闭面板不中断。
失败
单张失败不中断整批；结束后列出失败照片与原因，可只重试失败项。
持久化
地址、模型、每张数量、父级、写入方式保存在 <图库>/auto-keywords.json。
隐私
默认只连 127.0.0.1 / localhost；非本机地址显示警告，图片不出本机。

交互

  • 未连接时「生成关键字」不可用，先检测服务；检测结果同时验证所选模型是否支持图片输入。
  • 运行中点「停止并查看」：已完成的照片进入待确认，未完成的丢弃。
  • 待确认：照片行可展开/收起；× 移除单个关键字；取消勾选整张照片；计数实时更新。
  • 确认写入后按钮变为「撤销这一批」，只回退本批，不影响之后的编辑。

实现落点（全部在 extension/）

  • extension/src/auto_keywords.rs页面、状态机、后台队列、结果应用。
  • extension/src/vlm.rs本机 HTTP 客户端（GET/POST、超时、大小上限）、Ollama/OpenAI 两种请求与响应。
  • extension/src/prompt.rs提示词、JSON 容错解析、分类白名单、去重与清洗。
  • 原生只改一处数据：crates/ui-egui/locales/zh-hans.json 增加本页中文条目。
  • 不改 crates/ 任何逻辑；渲染用 Session::render_job，写入用 Session::execute_fn。
