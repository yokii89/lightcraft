# 地图相册持久化与自动增量设计

- 状态：已实现；自动同步在地理分类页运行，重新打开页面时会补齐期间的图库变化
- 日期：2026-11-13
- 范围：`lightcraft-extension`（`extension/`）
- 前置设计：[`01-扩展两级导航与地理位置分类设计.md`](01-扩展两级导航与地理位置分类设计.md)、[`02-地理分类地图视图设计.md`](02-地理分类地图视图设计.md)

## 1. 目标与产品决策

地理分类从一次性“选范围、跑反查、写关键字”变为绑定图库的地图相册。分类结果可跨页面和应用会话保留；首次打开或图库变化时自动补齐、更新、移除相册条目。

- 有有效 GPS 的图库照片自动进入相册，无需再次点击“开始分类”。
- 自动入册只记录地点分类结果，不改照片元数据或关键字。
- 写入关键字仍由用户进入评审页、检查地点并确认；整批仍是一个撤销步骤。
- 相册和评审都针对整个图库，因此移除地理分类页的范围选择器。自动关键字页仍保留共享的范围控件。
- 照片位置以目录中的当前 GPS 绘制；分类依据另存为 GPS 基准，GPS 改动后触发重分类。

## 2. 持久化格式

每个落盘图库使用独立文件 `<library>/geo-classify.json`。内存演示库、临时库没有稳定目录，只在当前进程中保留。文件属于可重建的派生索引，不是照片编辑数据；删除或损坏后，图库和关键字不受影响，下一次同步重建相册。

```json
{
  "version": 1,
  "parent": "地点",
  "photos": {
    "42": {
      "id": 42,
      "country": "中国",
      "city": "杭州",
      "iso": "CN",
      "distance": 8342.5,
      "lat": 30.25,
      "lon": 120.16
    }
  }
}
```

`photos` 是以稳定图库 `PhotoId` 为键的有序映射；同时保存 `id`，便于检查条目并重建映射。`lat`/`lon` 是 GeoNames 反查时的 GPS 基准。国家、城市、ISO 代码和距离是基准位置的离线反查结果。无匹配也保存一个空地点条目和 GPS 基准，避免每次打开都重复反查。

读文件最多读取 64 MiB。缺失、超限、JSON 损坏或版本不支持时按空相册处理，不阻塞页面，也不弹错误；全量同步会重新建立有效条目。写入序列化为紧凑 JSON，并使用 `lightcraft_catalog::safe_file::write_atomic`，中断或磁盘写入失败不会留下半个新文件。写入失败记录日志，内存状态继续工作，并在 5 秒后重试。连续变化合并为 500 ms 防抖写入。

父级关键字保存在相册文件中。照片当前名称和关键字不重复保存：它们从目录读取，避免文件重命名或确认写入后出现过期副本。相册和照片关键字是两个独立状态；撤销关键字写入只会让该照片重新出现在“待写入”列表，不会把照片移出相册。

## 3. 同步模型

同步由地理分类页的每帧 `pump` 驱动，不创建独立后台线程。页面显示时持续追踪图库变化；页面关闭期间不会在后台扫描，重新打开时会根据目录当前状态补齐。首次打开一个已有图库时执行全量发现，之后用目录修订历史做增量。

```text
载入图库代次
    ├─ 读该图库的 geo-classify.json（无效或缺失则空相册）
    ├─ 清除上一个图库的队列、快照和页面选择状态
    └─ 基线置空，要求全量发现

每帧 pump
    ├─ 处理到上一批队列排空后，比较 catalog.revision
    ├─ touched_since(基线) 可用：只检查触碰过的照片
    │      不可用：全量扫描并修剪已删除/失去 GPS 的条目
    ├─ 新照片或 GPS 与条目基准不同：排入反查队列
    ├─ 已删除、离开图库、视频或 GPS 无效/缺失：移除相册条目
    ├─ 分帧处理队列，限制每帧最多 400 张且最多约 4 ms
    ├─ 写入反查结果；队列排空后安排防抖保存
    └─ 按相册代次、目录修订和父级关键字刷新页面快照
```

队列处理期间不丢弃进行中的工作；等当前队列排空后，再按最新目录修订重建下一批。这样用户编辑 GPS 或导入照片时，最终一批会按目录最新值重新判断。目录的 `touched_since` 历史若已淘汰则返回 `None`，触发全量扫描，保证正确性优先于增量性能。

GeoNames 数据未下载时，同步保留队列并等待；现有“地名数据”卡片提供下载，下载状态轮询完成后页面会继续处理。数据文件存在但加载失败时，错误写入日志/页面状态，重试至少间隔 2 秒，避免每帧重复解析损坏文件。成功加载的数据按目录、文件大小和修改时间缓存。

相册快照包含可显示地点、待写入地点及无匹配计数。快照只对照片存在状态、元数据和文件信息变化敏感；评分、显影等与相册无关的目录修订只推进快照基线，不重新遍历相册。关键字父级改变会使待写入路径重新计算，但不会重新执行地理反查。

## 4. 页面与写入流程

Idle 页是相册主页，依次显示地名数据、地图相册和父级关键字。地图卡片显示已分类地点、同步状态、待写入数、无匹配数和无 GPS 数；正在同步时显示剩余队列数。本次会话新增数只作状态提示，不作为持久数据。

用户进入评审后，待写入集合由相册中尚未包含当前 `{父级}|{国家}|{城市}`（无城市时 `{父级}|{国家}`）关键字的照片构成。国家和城市组可在地图中检查、排除。确认操作重新依据当前目录元数据构造 `Op::Batch`，仅写新增关键字，通过 `Session::execute_fn` 提交为一个 `Geo Classify` 撤销步骤。已存在的同路径关键字（大小写无关）不会重复写入；没有变化时不提交空批次。

## 5. 状态边界与恢复

- 图库代次改变时，先丢弃旧图库的队列与快照，再读新图库文件；不得把同数值的 `PhotoId` 跨图库复用。
- 新图库没有文件、文件损坏或版本不兼容时，父级回到默认值“地点”，相册从空状态开始发现。
- 页面状态锁中毒时取回内部状态，保持页面可用；相册文件不可写不阻止评审和关键字写入。
- 同步可能在用户进入评审后继续更新相册。评审提交按照片当前元数据和当前 GPS 重新检查，已移除的照片跳过，已存在的关键字去重。
- “无 GPS”数量来自最近一次全量扫描；增量修订不为统计数字而重扫整个图库。下次全量扫描刷新该数量。

## 6. 测试与验收

存储测试覆盖 round-trip、无匹配条目、损坏 JSON、64 MiB 上限、未知版本、缺失文件、映射增删替换和 GPS 基准比较。同步测试覆盖首次发现、仅处理触碰照片、GPS 改动后重分类、删除或失去 GPS 后修剪、无匹配条目不重复排队、队列排空，以及图库代次切换时清除旧队列和状态。页面 headless 测试覆盖相册卡片、地图、待写入计数及自动化控件；现有批量写入/撤销测试确保仍为一个撤销步骤。

本地质量门：

```text
cargo fmt --all -- --check
cargo test -p lightcraft-extension
cargo clippy -p lightcraft-extension --all-targets -- -D warnings
```

真实磁盘图库的验收还需确认文件生成、关闭并重开后载入、期间新增照片自动入册，以及关键字确认/撤销后待写入数量正确。演示库只验证内存态，不证明磁盘恢复路径。
